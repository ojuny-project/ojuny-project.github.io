The template uses the dendritic pattern: flake-parts plus import-tree. Each
`.nix` file under `modules/` is a flake-parts module. A settings page is a file
that declares one or more `flake.modules.*` entries and carries an `@menu`
header.

The template is not a general NixOS starter. It is Ojuny's system shape:
numbered categories, settings pages, generated machine data, and a narrow local
namespace for values shared across pages.

Category folders are numbered to order the repository tree. The GUI does not
read folder names. It sorts by the `@menu category` string, then by `@menu
order`, then by display name.

The current categories are `01-Users`, `02-Core`, `03-Desktop`, `04-GUI`,
`05-Applications`, `06-Utility`, `07-System`, and `Patches`. The category string
is authoritative; the folder name is a convenience for humans.

## A page file

```nix
{ self, inputs, ... }:
{
  /* @menu
     displayname = "Networking";
     icon = "network-wired-symbolic";
     order = 20;
     description = "NetworkManager, firewall, hosts, DNS";
     category = "07-System";
  */
  flake.modules.nixos.system-networking = { config, pkgs, ... }: {
    /* @option widget = "switch"; label = "Enable NetworkManager"; */
    networking.networkmanager.enable = true;
  };

  flake.modules.homeManager.system-networking-hm = { ... }: {
    /* @option widget = "switch"; label = "Show NetworkManager applet"; */
    services.network-manager-applet.enable = true;
  };
}
```

A page can declare both a NixOS module and a Home Manager module in the same
file. That keeps the page self-contained.

## Host wiring

`flake.nixosConfigurations.<host>` is registered in
`modules/07-system/00-host.nix`. The host imports the pages it needs through
`modules/07-system/00-imports.nix`. The settings GUI follows the import graph,
so the host imports decide which menus are shown for that system.

## Generated and templated files

- `modules/07-system/00-hardware.nix` is generated by the setup script and has
  no menu. It is not meant to be edited by hand.
- `modules/07-system/facter.json` is generated by `generate-hw` from a
  `nixos-facter` report and read by the Hardware profile page.
- `modules/07-system/00-hardware-quirks.nix` is generated by
  `regenerate-hardware`. It imports one `nixos-hardware` profile, or nothing
  when the machine is unmatched, and has no menu.
- `modules/07-system/09-facter.nix` is the Hardware profile page. It selects a
  profile manually; `auto` reads `facter.json` against the table in
  `10-hardware-profile.nix`. A manual choice wins over automatic selection.
- `modules/01-users/01-user.nix` is templated, filled by the setup script, and
  has a menu. The account can be edited later in the GUI. The editor default is
  global, set by `03-user-editor.nix`, not per account.
- `modules/07-system/00-host.nix` registers the `nixosConfigurations` host
  entry.
- `modules/07-system/00-imports.nix` is the host import list that decides which
  pages are shown.
- `modules/07-system/00-ojuny-cli.nix` installs `ojuny-cli` and
  `ojuny-patches-cli`.
- `modules/07-system/00-secureboot.nix` is the optional Secure Boot page. It
  uses Lanzaboote, requires UEFI with systemd-boot, and is off by default.
- `modules/07-system/08-accessibility.nix` covers the screen reader, braille,
  contrast palette, color profile, and accessibility binds.
- `modules/07-system/_00-ssh-test.nix` is a temporary test module. Files whose
  names start with `_` are skipped by import-tree.
- `modules/07-system/02-networking.nix` holds the remote install options.
  `ojuny.network.deploy-rs.enable` installs `deploy-rs` and `nixos-anywhere` and
  enables SSH access. A manual template install uses the generated
  `00-hardware.nix` and no disko layout; the attended and unattended installers
  write their own disko layout into that file.
- Impermanence is the optional patch at
  `modules/patches/patch-impermanence.nix`, not a system module.
- `system.stateVersion` is set in `01-configuration.nix` and is never exposed
  as a GUI control. Only `home.stateVersion` is prompted by the setup script.
- `modules/patches/` contains the patch pages and the patch switch. `_gate.nix`
  is the import gate.
- `templates/` contains the scaffolds for new pages and patches.

## Patches

The template pre-includes seven patch copies: `patch-development`,
`patch-docker`, `patch-flatpak`, `patch-impermanence`, `patch-nixshell`,
`patch-remote-desktop`, and `patch-virtualization`. Most mirror the
`ojuny-patches` registry, which is the source of truth for patch names,
metadata, and content. `patch-impermanence` is not in the registry; the nearest
registry patch is `patch-home-snapshots`. Do not edit a pre-included copy only
in the template.

Additional patches are installed with `ojuny-patches install <id>`. The
installed module lands in `modules/patches/` and is imported by `00-patches.nix`
when `ojuny.patches` is enabled. There is no registry input; patches are local
files once installed.

## Shared namespaces

- `desktop.ojuny.*` comes from the desktop flake and is used unchanged by the
  desktop pages.
- Template-local values use the top-level `ojuny.*` namespace when they are
  shared across pages, including `ojuny.patches`, `ojuny.hardware.profile`, and
  `ojuny.network.deploy-rs`.
- A value that is only used on one page can annotate the real NixOS or Home
  Manager option directly.

## Adding a page

1. Create a numbered `.nix` file in the matching category folder.
2. Add an `@menu` header with a category and order.
3. Declare the NixOS and/or Home Manager module.
4. Annotate the user-facing assignments with `@option`.
5. Import the page from the host if it is not already imported.

## Flake outputs

- `nixosConfigurations.<host>` for each host.
- `nixosModules.default` and `homeManagerModules.default`, re-exported from the
  desktop flake.
- `packages.*` for local wrappers (`prepare-repo`, `regenerate-hardware`) and
  the re-exported GUI, desktop, and CLI packages.
- `apps.setup`, `apps.prepare-repo`, `apps.regenerate-hardware`,
  `apps.remote-setup`, `apps.prepare-remote-repository`, and
  `apps.remote-install`.
- `checks.hardware-profile`, which verifies the Nix hardware table matches the
  Python copy used by `regenerate-hardware`.
